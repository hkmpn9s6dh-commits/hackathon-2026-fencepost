# 07-UI · 《Fencepost》的界面与第一眼

> 闸 A 要的第 1–4 节。这里只管「评委第一眼会停下来吗」，不管功能。

## 1. 风格预设

**工程审计单（engineering audit sheet）**。不是产品落地页，是一份可以打印、可以放进工单、可以逐行核对的纸。

- 底：纸白 `#fbfaf7`；字：墨黑 `#1b1a17`；强调：锈红 `#8a2b06`（只给高严重度和"被拒"）
- 字体：正文衬线（Iowan Old Style / Songti SC），引文与行号等宽
- 版式：一条 2px 黑顶线 + 一条细底线的统计条，然后是行内两栏（承诺 / 实际）
- 禁：渐变、阴影、圆角卡片、图标集、深色底、动效

为什么是这套：同场 20 个提交几乎都是深色 + 渐变 + 大标题的"AI 产品"长相。一份纸白的审计单在列表里是**反着来的**，而反着来这件事本身就是信息：这东西是来核对的，不是来推销的。

## 2. 尺子（同场 5 件，每件写学哪一点）

赛题没有往届得奖作，所以尺子取**同一场比赛的公开提交**——同评委、同赛题、同媒介（README + 演示视频）。用 `api.github.com/search/repositories?q=openminion+hackathon` 找到 20 件，取 5 件。

| # | 作品 | 它做对了什么（要学的） | 它的弱点（不学的） |
|---|---|---|---|
| 1 | `jeffrey-graham/cortensor-openminion-hackathon`（Cortensor Sentinel） | 建筑块表格逐行对应到文件路径，评委不用猜；「8 real findings + merged upstream contribution」把 bonus 通道直接摆到台面上 | 通篇是规格表，读完不知道"我会在什么时候用它" |
| 2 | `predestinator/rulesminion`（RulesMinion） | 第一段就把自己缩小：「small, repeatable workflow rather than a multi-agent product」；「The valuable part is a grounded brief you can diff」——给自己划了边界，反而可信 | 受众窄（只服务打比赛的人），场景一眼看到头 |
| 3 | `ElTanque81/prejudge`（PreJudge） | 标题下一句话就把价值说穿：「Judge your hackathon project with the organizer's own rubric — **before the real judges do**」 | 功能面铺得宽（打分 + 修复 + 双语 + CI），第一屏信息密度偏高 |
| 4 | `faust-dark/veritas`（Veritas） | 四行 ASCII 流程图（Proposer → Critic → Judge → Verdict）比任何散文都快；「auditable evidence bundle」把抽象承诺变成了名词 | 三个 agent 的"论证"很难被外部核对，读者只能信它 |
| 5 | `Siven-cyber/daily-financial-agent`（Finance Agent） | 有活链接、有 badge、有真实运行数字；「Live deployment is separate from source updates」主动划清边界 | 场景太日常，和 Cortensor 的 builder 工作流关联弱 |

**从这五件里提炼的三条**（写进 README 的硬要求）：
1. 第一屏必须有一句话能说穿价值，且这句话里要有一个**别人不能说的话**（→ 本作：「a model may propose, never testify」）。
2. 必须有一张**能一眼看完的结构图**，不能只有段落（→ 本作：五行流程图，承诺 → 闸 → 配对 → 反方 → 账本）。
3. 所有数字都要能被第三方复算（→ 本作：审计自己的仓库，并把 4 条结果连同 `file:line` 一起贴出来）。

## 3. 一个记忆点

**「模型不许作证。」**

四层落到画面上：
1. README 第一段第二句就是这个规则；
2. 报告里有一节叫「模型提出但被逐字核对拒绝」，把被拒的引文一条条列出来；
3. 演示片里用 20 秒专门讲这三条被拒；
4. `ledger.json` 里 `dropped_quotes` 是顶层字段——不是日志，是证据。

可复述性检查：一个评委看完能用一句话向别人转述它，并且这句话不是"一个检查文档的工具"。

## 4. 主屏规格（报告页）

| 项 | 值 |
|---|---|
| 画布 | 1080px 内容宽，40px 边距，纸白底 |
| H1 | 40px / 行高 1.15 / 600；上方 11px 字距 0.22em 的小标 |
| 主张句 | 19px，紧贴 H1，一句说完结论（不是"报告如下"） |
| 统计条 | 4 格，34px 数字 + 12px 标签，2px 黑顶线 + 1px 细底线 |
| 引文块 | 等宽 12.5px，浅底 `#f2eee6`，左侧 2px 竖线 |
| 行号 | 等宽 11.5px，灰色，永远紧跟 `文件:行` |
| 600px 缩略图 | 统计条的四个数字与每行左侧的严重度色块仍须可辨；引文可截断 |
| 打印 | 去底色，24px 边距，不断行 |

验收方式：把 `report.html` 在 1440 / 1080 / 600 三个宽度各截一张，600 那张上必须还能读出「几条、几条高、哪一类」。
